TrendLens — How It Works

An upload-driven trend intelligence app. You drop in a market/innovation deck (.pptx/.pdf); AI extracts its full trend taxonomy strictly from the document, real Google Trends data is layered on for momentum, and a cross-file synthesis ranks the strongest megatrends. This page documents exactly what is stored, where, and what the AI is doing — end to end.

02 The stack & where things run

Two processes, one shared BigQuery dataset. The Next.js dashboard serves the UI and the read APIs; it also kicks off the heavy lifting by spawning detached Python subprocesses. All durable state lives in BigQuery — there is no separate app database.

Dashboard Next.js

Folder dashboard/ · runs at localhost:3000

  • React UI: reports list, report explorer, best megatrends, upload.
  • API routes under app/api/* query BigQuery directly via lib/bigquery.ts.
  • Auth: @google-cloud/bigquery using Application Default Credentials (ADC); project from BIGQUERY_PROJECT.

Pipeline Python

Folder src/ · spawned by the dashboard

  • src/pipeline.py orchestrates: extract → synthesize → measure.
  • Claude calls go through src/common.py → Anthropic API (ANTHROPIC_API_KEY).
  • BigQuery writes via the google-cloud-bigquery client (ADC, project from BIGQUERY_PROJECT).
The dashboard never talks to Claude itself. When you upload a file or click Measure Google Trends, the API route just spawn()s a Python module detached and returns immediately. All AI + Google Trends + BigQuery writes happen in Python.

03 End-to-end data flow

From a dropped file to a ranked dashboard. Each step is tagged by what kind of work it is and which table it writes.

1

Upload a deck  writes file

POST /api/upload  →  dashboard/src/app/api/upload/route.ts

The file is validated (.pptx/.pdf only), saved to uploads/<report_id>.ext, and a new report_id (rep_…) is minted. The route then spawns python -m src.pipeline <path> <report_id> detached and returns {status:"processing"} right away.

2

Extract taxonomy  AI · Claude reports + taxonomy_nodes

src/extract_taxonomy.py · run()

Text is pulled out of the file (python-pptx / pypdf), capped at 120,000 chars, and sent to Claude with the extraction prompt. Claude returns the full tree as JSON. Two more Claude calls then normalize & dedup behaviours and psychographics. Rows are flattened and written; any prior rows for this report_id are deleted first (idempotent re-run).

3

Synthesize best megatrends  AI · Claude megatrend_clusters

src/synthesize_megatrends.py · run()

Looks across all reports, asks Claude to merge equivalent megatrends into canonical clusters, then ranks them by real signals (file corroboration + rising-search count). Runs before the slow Google Trends step so the report is usable immediately.

4

Measure Google Trends  EXTERNAL trend_searches

src/map_searches.py → src/trends_browser.py

For each product/ingredient's search_term, a real Chromium browser pulls 12 months of Google Trends interest. Growth metrics (current interest, YoY %, rising flag) are computed and written. Best-effort & cached — already-measured terms are skipped. Re-triggerable any time via POST /api/measure/[id].

5

Dashboard reads it back  READS

app/api/report/[id], /api/reports, /api/best

The UI queries BigQuery for the report, its taxonomy nodes, and its trend searches, and joins them client-side into the megatrend → subtrend → detail explorer. The Best Megatrends page reads megatrend_clusters.

05 Everything the AI does

Every AI call is Claude Opus 4.8, reached through the Anthropic API (claude-opus-4-8, adaptive thinking, max_tokens 32000), via one helper: src/common.py · complete_json(). The app makes four kinds of AI call. There are no others.

AI call A — Taxonomy extraction 1 call per upload

Where: src/extract_taxonomy.py · EXTRACTION_PROMPT  ·  Input: the deck's text (≤120k chars). Output: the full taxonomy as JSON. Writes: reports.title + all taxonomy_nodes.

What it produces: megatrends → subtrends → {products, ingredients, behaviours, psychographics}; a search_term for every product/ingredient; a 1-line description for each behaviour/psychographic.

# Verbatim instruction — the grounding rule:
"Extract its trend taxonomy STRICTLY FROM THIS DOCUMENT
 — do not add anything that is not supported by the text."

# Form rules added in the recent quality pass (A):
behaviour      → observable verb phrase  e.g. "buys direct from manufacturer"
psychographic  → value/identity noun     e.g. "Convenience-seeking"
search_term    → short Google-typeable phrase

AI calls B — Normalize & dedup 2 calls per upload

Where: src/extract_taxonomy.py · NORMALIZE_PROMPT (one call for behaviours, one for psychographics). Input: the de-duplicated list of extracted names for that type. Output: a map raw → canonical label. Writes: applied before the taxonomy_nodes insert.

Why: the raw extraction repeats the same idea under many subtrends ("desire for convenience and personalization" ×3). This pass merges near-duplicates into one canonical label and drops repeats within a subtrend, so the chips read cleanly and consistently.

AI call C — Cross-file megatrend clustering 1 call per pipeline run

Where: src/synthesize_megatrends.py · CLUSTER_PROMPT. Input: every megatrend name across all reports + its source filename. Output: canonical clusters with member indices. Writes: all of megatrend_clusters.

Note: the AI only decides which names mean the same thing. The ranking is not AI — best_score is computed from real signals (file count + rising-search count). Falls back to one-cluster-per-megatrend if the call fails.

What the AI does NOT do: it does not invent trends, pull from outside knowledge, score opportunities, or decide rankings. Extraction is document-bound; clustering only groups names; momentum and ranking come from real Google Trends data and arithmetic.

06 External data — Google Trends (the only outside source)

EXTERNAL Implemented in src/trends_browser.py, driven by src/map_searches.py. This is not AI — it's a real measurement.

How it's fetched

  • A real Chromium session (Playwright) opens trends.google.com/trends/explore, geo US, timeframe today 12-m.
  • It captures the chart's own widgetdata/multiline response → weekly interest series. Throttled far less than the pytrends back-channel.
  • Batches of 5 terms, ~5s pacing between batches. Best-effort: a blocked batch yields no data, marked has_data=false.

How metrics are computed

map_searches.py · metrics_for()

  • current_interest = avg of last 4 weeks.
  • yoy_growth = current vs first 4 weeks, as %.
  • is_rising = yoy ≥ 15% AND interest ≥ 2.

Caching: terms already measured (with data) are skipped on re-runs, so coverage accumulates and re-measures are cheap.

08 Write map — who writes what, and how

Every BigQuery write is an idempotent replace: the module deletes the rows it owns for that scope, then loads fresh rows via a load job (not streaming, so deletes aren't blocked by the streaming buffer). Helper: src/common.py · load_json_rows().

TableWritten byScope of replaceTrigger
reportsextract_taxonomy.pyWHERE report_id=@ridUpload (then status updated by map_searches)
taxonomy_nodesextract_taxonomy.pyWHERE report_id=@ridUpload / re-extract
trend_searchesmap_searches.pyWHERE report_id=@ridPipeline step 4 or "Measure Google Trends"
megatrend_clusterssynthesize_megatrends.pyWHERE TRUE (full rebuild)After extraction & after measurement
Because writes are scoped deletes-then-loads, re-uploading the same file under the same report_id cleanly replaces it — no duplicates. That's exactly how the recent behaviour/psychographic quality fix was re-applied to the existing report.

09 What the AI grounds on (references)

The single most important property of this system: the trend content is traceable to the uploaded document, not to the model's training data.

AI stepWhat it's allowed to look atWhat it may NOT do
Extraction (A)Only the text of the one uploaded file (≤120k chars).Add trends, products, or claims not present in that file.
Normalize/dedup (B)Only the list of names already extracted from that file.Introduce new items — it only merges/relabels existing ones.
Clustering (C)Only the megatrend names + their source filenames, across reports.Rank, score, or weight — ranking is pure arithmetic on real signals.
Google TrendsReal public Google search interest (US, 12 months).n/a — not AI; a direct measurement.

So when you see a behaviour, a product, or a megatrend in the UI, its origin is: this slide deck (taxonomy) plus, for products/ingredients, real Google search momentum layered on top. Nothing in the trend tree is model-invented.
